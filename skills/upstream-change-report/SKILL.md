# 上游变更报告

此 skill 只读取和分析上游，不执行 rebase、merge、push 或其他写操作。

## 获取范围

1. 分别执行 `git fetch origin` 和 `git fetch upstream`。
2. 比较 `origin/main..upstream/main`，说明 fork 镜像尚未同步的腾讯上游变化。
3. 比较 `origin/main..origin/main_v2`，说明已同步上游或 fork 集成改动尚未进入长期
   集成主分支的内容。
4. 若用户指定功能分支，比较该分支与 `origin/main_v2`，找出会影响功能分支的集成
   主分支变化。
5. 记录每个范围的起点、终点 SHA 与提交日期；范围为空时明确说明没有新提交。

## 分析方法

1. 用提交标题初步归类为 `fix`、`feat`、`breaking`、`refactor`、`docs` 或其他。
2. 对可能影响当前任务的提交读取实际 diff 和相关测试，说明行为变化、影响文件和风险。
3. 将上游改动与本地未提交 diff 及功能分支 diff 的文件和行为交叉比对。
4. 仅在上游行为与本地需求及测试都吻合时，标记为“已覆盖”；只改到部分行为时标记为“部分覆盖”；否则标记为“未覆盖”。

不要仅凭相似标题、同名文件或相近关键词声称上游已解决问题。
一个本地提交包含多个行为时，必须拆分报告每个行为的上游证据与结论，不能按文件或
提交整体标记为“已覆盖”。

## 报告格式

按以下顺序输出：

1. 比较范围：分支、SHA、提交数量和日期区间。
2. 上游到镜像：腾讯修复、功能及破坏性变化。
3. 镜像到 `main_v2`：尚待集成的提交。
4. `main_v2` 到功能分支：功能分支需要吸收的变化。
5. 与 fork 的关系：`已覆盖`、`部分覆盖`、`未覆盖`，并列出证据。
6. 建议动作：同步到 `origin/main`、合并到 `main_v2`、删除 fork 重叠改动、保留
   未覆盖差异，或保持不动。

报告结束时列出建议保留与建议删除的 fork 文件。没有充分证据时，结论必须是“需要进一步检查”，而不是猜测。
